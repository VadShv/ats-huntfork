## Согласованные решения

1. **Порядок:** Настройки (тех-долг) → кнопки → поля → фильтры.
2. **UiButton:** расширяем компонент (`outline`/`success`, `size="xs"`,
   `icon-left`/`icon-right`, `block`).
3. **Охват рефактора:** помодульно, пошагово (одна итерация = один модуль/экран).
4. **Тех-долг Настроек:** убран в Этапе 1.1.
5. **1.2 (новые разделы Настроек):** НЕ делаем — у модулей уже есть свои страницы,
   заглушки не нужны. Приведём к стандарту, когда набор страниц устоится.
6. **1.3 (макет Настроек):** отложен — будут появляться новые страницы, унифицируем
   позже одним заходом.
7. **Формат:** этот письменный план + сводная таблица рисков ниже.

### Что «единый стиль» значит на практике

- **Сейчас единообразны** экраны/компоненты, которые используют `Ui*`.
- **Новые страницы** — делать проще: `<UiButton variant="primary" :icon-left="Plus">`
  вместо ручных классов; вид, тёмная тема, focus, loading/disabled — из коробки;
  витрина `/dashboard/design-system` показывает все варианты.
- **Старое ядро** (~992 сырых кнопки) станет единым только после Этапа 2.2.
- **Правило на будущее:** на новых страницах — только `Ui*`, без сырых
  `<button>/<input>/<select>/<textarea>` (см. «Принципы» ниже).

## Принципы (definition of done)

1. Никаких сырых `<button>/<input>/<select>/<textarea>` с инлайн-Tailwind в
   продуктовых экранах — только `Ui*` (исключение: карточки откликов/резюме).
2. Один смысл — один компонент/вариант (не копипастить классы).
3. Витрина `design-system.vue` = фактическому API компонентов.
4. Каждая итерация — один модуль/экран, отдельный коммит, проверка светлой/тёмной темы.
5. Токены семантические (`brand/surface/success/danger/...`), без `emerald/primary`-разнобоя.
