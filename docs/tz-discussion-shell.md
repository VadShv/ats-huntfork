# ТЗ · «Обсуждение» — новая оболочка (этапы 0–1)

Дата: 07.10.2026 · Основание: `docs/discussion-module-redesign.md` (PR #19) и согласованный прототип · Исходное состояние модуля описано в `docs/tz-collaboration-hub.md` (этапы 1–4 реализованы; этап 5 этим ТЗ заменяется).

## 1. Цель

Убрать перегруз из модуля обсуждения отклика: оставить в кадре только то, что нужно для разговора о кандидате, а редкие действия спрятать в два меню. Смену этапа сделать частью отправки сообщения (как в Хантфлоу). Данные, API и права не ломать.

Границы: «Чат с кандидатом» (`CommsChatPanel`) не трогаем и ни с чем не объединяем. Комментарии hh.ru остаются во внутреннем обсуждении. Опросы отложены. Отправка — Ctrl/Cmd+Enter.

## 2. Что видит пользователь

```
┌ Обсуждение · видит команда · [12]        [Другие отклики 2 ▾]  🔍  ⋯ ┐
│ ▍📌 закреплённое / контекст ИИ (скрининг · риск)          [Контекст ▾] │
├──────────────────────────────────────────────────────────────────────┤
│ лента: группы сообщений, ответы с цитатой, события этапов,            │
│ карточки ИИ (сводка, ответ, снимки), hh-комментарии                   │
├──────────────────────────────────────────────────────────────────────┤
│ [+] Написать команде…                        [⟶ Этап ▾] [🔒] [➤]     │
│     N печатает…                                                       │
└──────────────────────────────────────────────────────────────────────┘
```

Постоянно видимых элементов управления — 7: «Другие отклики», поиск, «⋯», полоса закреплённого, «+», «Этап», замок (+ кнопка отправки).

### 2.1 Шапка (`ApplicationCommentThread.vue`)
- Заголовок «Обсуждение», подпись «видит команда», счётчик сообщений.
- «Другие отклики (N) ▾» — только если у кандидата > 1 отклика. Список: вакансия, этап (цветная точка), число сообщений, бейдж непрочитанных. Текущий отклик помечен. Выбор другого открывает его ленту в режиме чтения с полосой «Просмотр · {вакансия} · только чтение · Вернуться».
- Поиск (иконка): строка поиска с чипами-фильтрами «Внутренние · ИИ · События». Esc закрывает. Поиск подсвечивает совпадения и листает их ↑/↓.
- «⋯»: Участники (N) — раскрывает `WatcherPanel`; фильтры ленты (те же три, переключатели); «Синхронизировать с hh.ru» — только если отклик связан с hh.
- Удалено из шапки: кнопка ИИ-резюме, кнопки перевода по этапам (`InlineStageActions`), постоянная строка фильтров, счётчик подписчиков.

### 2.2 Полоса закреплённого (`DiscussionPinnedBar.vue`, новый)
- Элементы: закреплённые сообщения (`is_pinned`, по убыванию `pinned_at`) и один элемент «Контекст ИИ» (балл скрининга, уровень риска, «устарело»), если есть данные.
- Клик по полосе — переход к закреплённому сообщению (прокрутка + подсветка) и переключение на следующий элемент; счётчик «k/N».
- «Контекст ▾» раскрывает блок с деталями скрининга и риска (перенесён из `DiscussionContextWidgets.vue`, который удаляется). Авто-раскрытие при высоком риске или низком балле сохраняется.
- Полоса скрыта, если нет ни закреплений, ни данных ИИ.

### 2.3 Лента
- Группировка Telegram-style остаётся (`useCommentGroups`).
- Ответ показывает цитату родителя (автор + первая строка); клик по цитате — переход к оригиналу. Ответ рендерится без отступа-лесенки.
- ИИ-сводки рендерятся в ленте по времени (не прибиты сверху), карточка сворачивается до 3 строк.
- Новый тип записи `stage_comment`: сообщение, отправленное вместе со сменой этапа. Рендер: пилюля «{автор} ⟶ перевёл(а) на этап {X}» и под ней пузырь с текстом. Парное событие `stage_event` (тот же `toStageId`, |Δt| < 15 с) скрывается, чтобы не дублировать.
- Блок «Прочитали» переносится в правый нижний угол ленты, мелко.
- Убраны глобальные горячие клавиши j/k/c и «/» на `document`.

### 2.4 Поле ввода (`ApplicationCommentComposer.vue`)
- Одна строка: `+` · textarea (авторост до ~6 строк, строка прикреплённых файлов под ней) · «⟶ Этап ▾» · 🔒 · ➤.
- Меню «+»: Файл (input file / drag-and-drop как раньше), Шаблон ▸ (список `/api/message-templates`), Прикрепить результат ▸ (ИИ-скрининг / Оценка рисков → `POST /comments/snapshot`), Спросить ИИ (вставляет `@ai `), Сводка обсуждения (`POST /comments/summarize`). Ввод «/» в пустом поле открывает это же меню.
- «Этап ▾»: список этапов (без текущего, скрытых и архивных), подписи «следующий», «отказ». Выбор превращает чип в «⟶ {этап} ✕», плейсхолдер — «Комментарий к переводу…». Отправка с текстом → `POST /comments { moveToStageId }` (одна запись `stage_comment` + перевод). Отправка без текста → `PATCH /stage`. Ошибки перевода (422 «нужен комментарий» и др.) — тостом, этап остаётся выбранным.
- 🔒: переключатель внутреннего сообщения, виден только ролям из `INTERNAL_VISIBLE_ROLES`. Включён — фон поля жёлтый, плейсхолдер «Внутренняя заметка…». Если во внутреннем сообщении упомянут заказчик (роль `hiring_manager`/`external_recruiter` из автодополнения) — предупреждение над полем с кнопкой «Сделать видимым».
- Удалены: умные подсказки, slash-палитра как отдельный компонент, панель «Прикрепить результат», текстовая подсказка про Ctrl+Enter (остаётся в `title`). Стикеры по просьбе пользователя возвращены (08.10.2026) — пунктом «Стикер ▸» в меню «+», сетка из `public/stickers/manifest.json`, токен `:sticker[id]:`; сообщение из одного стикера показывается без плашки и крупнее.
- Остаются: @-автодополнение, черновик в localStorage, индикатор «печатает», Ctrl/Cmd+Enter.

## 3. Сервер

- `shared/access/discussion.ts`: `INTERNAL_VISIBLE_ROLES`, `canSeeInternalRole(role)`. `server/utils/comments/visibility.ts` импортирует оттуда; клиент использует тот же хелпер (исправление бага: рекрутёр с ролью `member` не видел переключатель).
- `createApplicationCommentSchema`: `+ moveToStageId?: string`.
- `POST /api/applications/:id/comments` при `moveToStageId`: сначала `moveApplicationStage({ comment: body.slice(0,500), via: 'manual' })` (все проверки перехода внутри), затем комментарий с `kind = 'stage_comment'`, `payload_json = { fromStageId, fromStageName, toStageId, toStageName, toStageColor, movedAt }`. Ошибка перевода — ответ 4xx до записи комментария.
- `GET /api/applications/:id/comments` теперь отдаёт `isPinned` и `pinnedAt` (раньше поля не выбирались — закрепление сохранялось в БД, но лента его не показывала).
- Лента скрывает `stage_event`, парное к `stage_comment` (тот же целевой этап, разница по времени < 15 с), чтобы перевод не отображался дважды.
- Миграций нет: `kind` — текстовое nullable поле.

## 4. Удаляемые файлы
`SmartSuggestions.vue`, `useSmartSuggestions.ts`, `StickerPicker.vue`, `SlashCommandPalette.vue`, `InlineStageActions.vue`, `TemplatePicker.vue` (список шаблонов — внутри меню «+»), `DiscussionContextWidgets.vue` (перенесён в `DiscussionPinnedBar.vue`). Серверные API опросов, стикеров и шаблонов не трогаем. i18n-блоки `slash`, `smart_suggestions`, `stickers` удаляются.

## 5. Приёмка
1. Рекрутёр с org-ролью `member` видит замок и может отправить внутреннее сообщение; `hiring_manager` замка не видит и внутренние не получает.
2. Ответ на сообщение показывает цитату; клик по цитате прокручивает к оригиналу.
3. Выбор этапа + текст + Ctrl+Enter → в ленте одна запись «перевёл на этап X» с текстом, этап отклика изменён, дубля события нет.
4. Выбор этапа без текста → этап изменён, в ленте обычное событие.
5. Возврат из терминального этапа без текста → тост «нужен комментарий», ничего не записано.
6. «+» → Прикрепить результат → в ленте снимок; «Сводка» → карточка ИИ по времени.
7. Закреплённое сообщение видно в полосе; клик ведёт к нему; при двух закреплённых — листание.
8. У кандидата с двумя откликами — «Другие отклики (1)», просмотр чужого отклика только для чтения с полосой «Просмотр».
9. В шторке воронки (`compact`) всё помещается в 640px без горизонтальной прокрутки.
10. Юнит-тесты зелёные; `vue-tsc` по изменённым файлам без новых ошибок.

## 6. Этап 2 — реализовано в этой же ветке

### 6.1 Автоимпорт комментариев hh.ru при любом способе добавления резюме (решение №4)
- `server/utils/hh/commentImport.ts`: задача очереди принимает `{ candidateId, orgId, applicationId?, hhAccountId? }`. Целевой отклик — переданный, иначе последний отклик кандидата с hh-источником (`hh`, `hh_sourcing`, `hh-extension`, `extension-capture`), иначе последний отклик. Токен — переданный аккаунт → связка вакансии → аккаунты организации.
- Триггеры: синхронизация откликов (`hh/sync.ts`, с `applicationId` и `hhAccountId` связки), импорт из сорсинга (`sourcing-candidates/[id]/import.post.ts`), импорт резюме расширением и по ссылке (`hh/importResume.ts`). Ручная кнопка «Синхронизировать с hh.ru» сохранена.
- Импортированные комментарии — `is_internal = true` (константа `HH_IMPORTED_COMMENT_IS_INTERNAL`): это внутренняя информация рекрутёров, заказчик их не видит. В ленте показываются как «с hh.ru», с именем автора на hh и датой комментария на hh.
- После вставки новых записей задача шлёт `notifyThreadChanged` — открытый тред обновляется сам.
- Ограничение: резюме, захваченные расширением из HTML (`capture-confirm`), не содержат `owner.id` соискателя — для них импорт невозможен, пока у кандидата не появится hh-резюме через API.
- Попутно исправлено: в `POST /api/hh/comments/sync` не был импортирован `and` из drizzle — ручная синхронизация падала.

### 6.2 Личные закрепления
- Таблица `comment_pin_personal` (миграция `0125_comment_pin_personal.sql`): `(comment_id, user_id)` уникальна, каскад по сообщению/пользователю.
- `POST /comments/:commentId/pin` принимает `{ scope: 'all' | 'me' }`. `all` — как раньше (`is_pinned`, нужен `application:update`, тред уведомляется); `me` — личная запись, достаточно `application:read`, других участников не трогает.
- `GET /comments` отдаёт `isPinnedByMe`. Меню сообщения: «Закрепить для всех» / «Закрепить для себя». В полосе закреплённого личные идут после общих, с подписью «закреплено для меня» и серым маркером.

### 6.3 Пагинация ленты
- `GET /comments?limit=50&before=<ISO>` — курсор по времени сообщения `COALESCE(hh_synced_at, created_at)`, от новых к старым; ответ `{ data (старые сверху), hasMore, oldestAt, total }`. Прежний `page` (offset от старых) отдавал первые 100 сообщений и терял свежие — удалён.
- Клиент: первая загрузка — последние 50; «Показать более ранние» сверху ленты и автоподгрузка при прокрутке к началу с сохранением позиции. Рефетч по SSE запрашивает столько, сколько уже загружено (до 200), чтобы не терять подгруженную историю.
- Пока есть незагруженная история, события этапов старше первого загруженного сообщения не показываются.

## 7. Визуальная версия 1 — реализовано в этой же ветке

Источник: `docs/discussion-vision.md` §3–4 (ветка `docs/discussion-vision`, PR #21), HTML-прототип согласован отдельно. Это только клиентская отрисовка плюс два поля в одном GET; схема БД и права не менялись.

### 7.1 Пространство на всю высоту
- `ApplicationCommentThread.vue`: секция фиксированной высоты (`calc(100vh − 10rem)`, минимум 560px; в шторке и на странице вакансии — `min(72vh, 760px)`), шапка и композер не прокручиваются, лента — между ними. Прежние ограничения `max-h-[560px]/[420px]` удалены.

### 7.2 Шапка-паспорт
- Первая строка: имя кандидата · название вакансии. Имя приходит из `GET /api/candidates/:id/discussion-tabs` (добавлено поле `candidate { firstName, lastName }`), название — из текущего отклика списка.
- Вторая строка: сегменты этапов воронки (`GET /api/applications/:id/stages`: этапы верхнего уровня без архивных и скрытых, по `displayOrder`; пройденные — серые, текущий — в цвет этапа, отказ — отдельный тусклый сегмент справа) и подпись «Этап X · N дней» по `application.stage_changed_at` (добавлено в `discussion-tabs` как `stageChangedAt`). Склонение дней — в коде, без плюрал-правил i18n.
- Справа: стопка участников (до трёх аватаров + «+N», клик открывает панель участников), «Другие отклики», поиск, «⋯». После перевода этапа из композера сегменты и подпись обновляются (`fetchStages`).

### 7.3 Рельса времени и события
- Лента обёрнута в `.disc-rail` (`main.css`): вертикальная линия под аватарами, отступ задаётся переменной `--disc-pad`. Все элементы ленты подняты над линией (`relative z-[1]`).
- `ThreadStageEvent.vue`: точка в цвет этапа стоит на рельсе; строка «Кто перевёл на ● Этап (из Y) · время». Прежняя иконка ветки убрана.
- День-чипы «Сегодня / Вчера / пн, 5 октября» между днями; кнопка «Показать более ранние» — в том же стиле.

### 7.4 Цвета авторов
- `authorHue(id)` (`useDiscussionColors.ts`): восемь оттенков oklch по хэшу id пользователя, одинаковые во всех тредах; бирюза ИИ (180) исключена. Оттенок задаётся переменной `--h` на строке сообщения; классы `.disc-avatar` (градиентный аватар с инициалами «ИФ»), `.disc-author` (имя), `.disc-quote` (кромка цитаты — в цвет автора исходного сообщения). Та же палитра — в стопке участников и в «прочитали».
- Тест `tests/unit/discussion-author-hue.test.ts`.

### 7.5 Внутреннее — кромкой, ИИ — единым языком
- `ApplicationCommentItem.vue`: пузырь нейтральный (`surface-100/80`), своё — лёгкий брендовый; внутреннее — янтарная кромка слева 3px и подпись «🔒 внутреннее» без сплошной заливки; ответ ИИ и снимок скрининга — бирюзовая кромка; снимок риска — янтарная.
- Аватар ИИ — искра на бирюзовом градиенте; `AiSummaryCard.vue` и `CommentSnapshotWidget.vue` — та же кромка и искра. Снимок скрининга раскрыт сразу и показывает критерии полосками (цвет по тем же порогам 75/40, что у текста); снимок риска свёрнут.
- Комментарий с hh.ru: автором показывается имя с hh (`hhAuthorName`), бейдж «hh.ru ←» сохранён; прежнее «Система» убрано.

### 7.6 Действия по наведению
- Реакции: полоса чипов под сообщением показывается только когда реакции уже есть; первая реакция ставится из действий по наведению (кнопка-смайл рядом с «⋯») — лента не «дышит» пустыми кнопками. Набор эмодзи вынесен в `useReactionEmojis.ts` (совпадает с allow-list сервера).

### 7.7 Разделитель «Новые сообщения»
- Тред при открытии запрашивает `GET /api/applications/:id/readers`, берёт мою `lastReadAt`, находит первое чужое сообщение новее неё (без ИИ-резюме) и ставит перед его группой разделитель с короткой подсветкой. Лента открывается на разделителе, а не внизу (в `useThreadScroll` добавлено `suppressAutoScrollOnce()`); кнопка «вниз» показана. Если я открываю тред впервые — разделителя нет, лента внизу.
- Отметка прочтения (`POST /read`) и уведомления (`markRead`) теперь ставятся тредом после вычисления разделителя; `ReadReceipts.vue` получает список прочитавших пропсом (один запрос вместо двух), себя в стопке не показывает.

### 7.8 Движение
- `.disc-rise` — появление сообщения и события (180 мс, без размытия); `.disc-glow` — подсветка разделителя; `.disc-flyer` — перелёт чипа этапа из композера к рельсе при отправке (`flyStageChip()` в композере, только если этап реально сменился). Всё отключается при `prefers-reduced-motion`.

### 7.9 Пустое состояние
- Иконка, заголовок «Здесь начнётся разговор о кандидате», подсказка про видимость для заказчика и три действия: «Написать команде» (фокус в поле), «Спросить @ai о кандидате» (вставляет `@ai`), «Прикрепить результат скрининга» (вызывает прикрепление снимка). Композер экспортирует `askAi()` и `attachScreeningSnapshot()`.

### 7.10 Приёмка визуальной версии
- Светлая и тёмная темы, компактный режим (шторка, страница вакансии), пустой тред, тред с историей > 50 сообщений (подгрузка не ломает рельсу и день-чипы).
- Перевод этапа из композера: сегменты и подпись в шапке меняются, чип улетает, в ленте появляется точка этапа.
- Повторное открытие треда после чужих сообщений: разделитель «Новые сообщения» стоит перед первым непрочитанным, лента открывается на нём.
- Заказчик (`hiring_manager`): внутренних сообщений нет, кромка и замок у видимых сообщений не появляются.

## 9. Исправление реакций (08.10.2026)

Симптом: реакция ставится, но чип под сообщением не появляется (или снятая реакция «возвращается»). Причины и исправления:

- `DELETE …/reactions/:emoji` получал параметр percent-encoded и не находил строку — реакция не удалялась, а SSE-рефетч возвращал её в UI. Теперь эмодзи декодируется (`decodeReactionEmoji`) и нормализуется к NFC.
- `POST …/reactions` падал на уведомлении, если у комментария нет автора-пользователя (hh-импорт, системные) — `createNotification` получал `userId: null`. Теперь уведомление отправляется только при наличии автора и не роняет запрос.
- Клиент полагался на оптимистичное обновление и полный рефетч по SSE. Теперь POST и DELETE возвращают актуальный сгруппированный список `reactions`, клиент подменяет им локальное состояние сразу (`useApplicationComments.toggleReaction`), а ошибки показываются тостом с кодом.
- Общий allow-list эмодзи вынесен в `server/utils/comments/reactions.ts`.
