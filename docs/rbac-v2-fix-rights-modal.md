# Доработка UI: модалка «Индивидуальные права» (AccessMemberRightsModal)

> Файл: `app/components/AccessMemberRightsModal.vue` (Спринт 5 #4).
> Две проблемы UX по фидбэку владельца. Низкий риск (чисто presentational,
> серверная логика прав/overrides НЕ трогается).

---

## Проблема 1 — модалка полупрозрачная / нечитаемая 🔴 (баг)

**Причина (найдена и подтверждена):** фон модалки задан `bg-surface-0
dark:bg-surface-900` (строка 79) и у `<select>` (строка 110). Токена
**`surface-0` в теме НЕ существует** — есть `surface-50 … surface-950`.
Несуществующий класс не применяется → фон прозрачный.

**Подтверждение (фидбэк владельца):** в ТЁМНОЙ теме модалка читаема, в СВЕТЛОЙ —
нет. Это ровно потому, что `dark:bg-surface-900` — валидный (тёмная тема работает),
а светлый `bg-surface-0` — несуществующий (светлая тема остаётся прозрачной,
сквозь неё виден оверлей `bg-black/40`). Баг ТОЛЬКО в светлой теме.

**Фикс:** заменить `bg-surface-0` → `bg-white`, `dark:bg-surface-900` ОСТАВИТЬ
(он рабочий):
- контейнер модалки (стр. 79): `bg-white dark:bg-surface-900`.
- `<select>` (стр. 110): `bg-white dark:bg-surface-900`.
Итог класса: `... bg-white dark:bg-surface-900`.

**Проверить заодно:** нет ли `surface-0` в других местах нового кода Спринта 5
(`grep -rn "surface-0" app/`). Если есть — поправить там же.

## Проблема 2 — права плохо сгруппированы 🟠 (UX)

Группировка по `category` уже есть (стр. 44-50), но оформлена слабо:
- заголовок секции = сырой ключ категории (`candidates`, `jobs`…) без русского
  названия (стр. 94);
- нет визуального разделения секций (плоский список);
- технический ключ права (`candidate:read:contacts`) показан моноширинным серым —
  визуальный шум.

**Фикс:**
1. **Человекочитаемые заголовки категорий** (RU): маппинг ключ → название.
   Категории из каталога: `org`, `members`, `jobs`, `candidates`, `applications`,
   `interviews`, `documents`, `comments`, `scoring`, `ai`/`integrations`,
   `sourceTracking`, `pipeline`, `audit`, … (полный список — из
   `shared/access/catalog.ts`). Пример маппинга:
   - jobs → «Вакансии», candidates → «Кандидаты», applications → «Отклики»,
     interviews → «Интервью», documents → «Документы», comments → «Комментарии»,
     scoring → «Оценка/скоринг», ai → «AI и промпты», integrations →
     «Интеграции», members → «Участники и роли», org → «Организация»,
     pipeline → «Воронки», sourceTracking → «Источники», audit → «Журнал».
   - Хранить маппинг лучше в одном месте (напр. рядом с каталогом в
     `shared/access/`), чтобы переиспользовать и не дублировать RU-строки.
2. **Визуальные секции:** каждую категорию — как карточку/блок с явным
   заголовком (иконка категории опционально), отступ между секциями, чтобы
   «Вакансии» и «Кандидаты» читались раздельно.
3. **Убрать/спрятать технический ключ** из основного вида: показывать `labelRu`
   крупно, ключ (`p.key`) — только как подсказку (title/hint при наведении) или
   мелко-вторично. Убрать моноширинный серый шум.
4. **Порядок категорий** — осмысленный (самые частые сверху: Кандидаты, Вакансии,
   Отклики, Интервью… далее служебные). Задать явный порядок, а не алфавит/как в БД.
5. (Опционально) **Поиск/фильтр по правам** сверху модалки — если прав много,
   быстрый фильтр по названию. Не обязательно в первой итерации.

## Что НЕ трогать
- Серверную логику overrides (`/api/access/members/:id/overrides` — валидация,
  deny-wins, транзакция, bump версии) — оставить как есть, она корректна.
- Модель прав, каталог значений — не менять (только RU-подписи категорий).
