# ТЗ · Обсуждение отдельным окном

Дата: 08.10.2026 · Статус: к реализации · Основание: идея C2 из `docs/discussion-vision.md` §2.3, новая оболочка `docs/tz-discussion-shell.md` (PR #20). Зависимость: ветка `feat/discussion-shell` (визуальная версия 1 — тред умеет растягиваться на всю высоту).

## 1. Цель

Дать рекрутёру возможность вынести обсуждение одного отклика в отдельное окно браузера без меню и шапки приложения — чтобы во время звонка, калибровки с заказчиком или работы с воронкой держать тред на втором мониторе и писать в него, не уходя со страницы, где идёт основная работа.

Что должно измениться для пользователя:
- в любом месте, где виден отклик (страница отклика, шторка воронки, страница вакансии, карточка кандидата, страница интервью), есть действие «Открыть обсуждение в окне»;
- открывается узкое окно: шапка-паспорт · полоса закреплённого · лента · композер, ничего лишнего;
- окно одно: повторный клик из любой страницы переключает уже открытое окно на нужный отклик, а не открывает второе;
- всё, что сделано в окне (сообщение, перевод этапа, закрепление), сразу видно в основном окне, и наоборот.

Чего не делаем: не меняем схему БД, права, API обсуждения; не создаём вторую реализацию треда — используется тот же `CandidateDiscussionTabs`.

## 2. Что видит пользователь

### 2.1 Откуда открывается

| Поверхность | Где кнопка | Какой отклик открывается |
|---|---|---|
| Страница отклика `dashboard/applications/[id].vue` | Меню «⋯» треда — пункт «Открыть в окне» (первым, с иконкой `ExternalLink`) | текущий |
| Шторка воронки `ApplicationDetailDrawer.vue` | Тот же пункт «⋯» внутри треда (компонент общий) | отклик шторки |
| Страница вакансии `jobs/[id]/index.vue` (секция профиля) | Тот же пункт «⋯» | выбранный в воронке |
| Карточка кандидата `candidates/[id].vue`, вкладка «Отклики» | Иконка `MessageSquare` с бейджем непрочитанных на каждой карточке отклика, рядом с названием вакансии | тот отклик, на карточке которого нажали |
| Страница интервью `interviews/[id].vue` | Кнопка «Обсуждение» в ряду действий шапки (рядом с «Перенести») | `interview.applicationId` |

Пункт в «⋯» треда скрыт, если тред **уже открыт в окне** (роут `.../discussion`) — вместо него пункт «Открыть карточку отклика» (переход в основное приложение в новой вкладке). На ширине экрана меньше 1024px пункты окна не показываются — на мобильных и планшетах попап бессмыслен.

### 2.2 Само окно

Роут `/dashboard/applications/:id/discussion`. Лейаут `default` (без меню и шапки; баннер `ViewAsBanner` остаётся — он показывает режим «смотрю как»). Содержимое — одна колонка на всю высоту окна:

```
┌──────────────────────────────────────────────┐
│ ● HuntFork · Обсуждение            [↗ карточка]│  ← мини-строка 32px: логотип-точка, подпись, ссылка в карточку
├──────────────────────────────────────────────┤
│ Анна Смирнова · Senior Backend Engineer       │
│ ▬▬▬▬▬▬▬▬▬▬ Этап Техсобес · 4 дня   ◯◯◯ +2 ⋯ │  ← шапка-паспорт треда (как есть)
├──────────────────────────────────────────────┤
│ ✦ Скрининг 82 · Риск: средний   контекст 1/2 │  ← полоса закреплённого (как есть)
├──────────────────────────────────────────────┤
│                                              │
│   лента с рельсой                            │
│                                              │
├──────────────────────────────────────────────┤
│ [+] Сообщение команде…        [→ Этап] 🔒 ➤  │  ← композер (как есть)
└──────────────────────────────────────────────┘
```

- Мини-строка нужна, чтобы окно без шапки приложения оставалось узнаваемым и из него был выход в карточку. Ссылка «↗ карточка» открывает `/dashboard/applications/:id` в **основной** вкладке (через `window.opener`, если жив, иначе новой вкладкой).
- Тред занимает `100vh − 32px`: `ApplicationCommentThread` получает проп `fill` (новый), который заменяет фиксированную высоту секции на `h-full` и убирает скругление/рамку.
- Переключатель «Другие отклики» в окне остаётся: смена отклика внутри окна меняет URL (`router.replace`), чтобы перезагрузка окна открывала тот же тред.
- Заголовок вкладки окна: `«Анна Смирнова · Обсуждение — HuntFork»`, при непрочитанных — префикс `(2)`. Это видно в панели задач ОС.

### 2.3 Поведение одного окна

- `window.open(url, 'huntfork-discussion', 'popup=yes,width=560,height=900,left=…,top=…')`. Имя окна фиксированное — браузер переиспользует его: при повторном вызове с другим URL уже открытое окно переходит на новый отклик и получает фокус (`win.focus()`).
- Размер по умолчанию 560×900, позиция — правый край текущего экрана (`screen.availWidth − 580`). Последние размер и позицию запоминаем в `localStorage` (`discussion-window:bounds`) и используем при следующем открытии; сам браузер их тоже помнит для именованных окон, но не во всех.
- Если браузер заблокировал попап (`window.open` вернул `null`), показываем тост «Разрешите всплывающие окна для HuntFork» и открываем роут обычной новой вкладкой.
- Закрытие основной вкладки окно не закрывает — это нормально: окно самостоятельно.

### 2.4 Синхронизация между окнами

Все данные треда и так приходят по SSE (`thread-stream`): новое сообщение в окне появится в карточке через рефетч, и наоборот. Отдельно нужна синхронизация **этапа**: карточка отклика, воронка и список «Другие отклики» в основном окне должны обновиться, когда этап переведён из попапа.

- `BroadcastChannel('huntfork-discussion')`. Сообщения:
  - `{ type: 'stage-changed', applicationId, payload: StageMoveResult }` — шлёт тот, кто перевёл; получатели вызывают тот же обработчик, что и при `@stage-changed` от треда (`handleStageChanged` / `handlePipelineStageChanged`), если `applicationId` совпадает с открытым у них.
  - `{ type: 'window-opened', applicationId }` / `{ type: 'window-closed' }` — чтобы в основном окне пункт меню показывал «Обсуждение открыто в окне → показать» и по клику просто фокусировал окно.
  - `{ type: 'focus-request', applicationId }` — основное окно просит попап переключиться (резерв для случая, когда `window.open` по имени не вернул ссылку).
- Черновики (`localStorage`, `draft:comment:<applicationId>`) общие автоматически. Чтобы начатый в карточке текст появился в окне без перезагрузки, композер слушает `storage`-событие по своему ключу и подхватывает черновик, если поле пустое.
- Отметка прочтения: окно и карточка оба ставят `POST /read` — конфликта нет. Разделитель «Новые сообщения» показывается в том окне, которое открылось первым после чужих сообщений; во втором его не будет — это ожидаемо.

### 2.5 Непрочитанные в карточке кандидата

На карточке отклика во вкладке «Отклики» кандидата — иконка `MessageSquare` и число непрочитанных из `useUnreadComments().unreadCount(app.id)` (уже используется в `CandidateDiscussionTabs`). Клик по иконке открывает окно; клик по названию вакансии — как сейчас, страницу отклика.

## 3. Реализация

### 3.1 Клиент — новые файлы

**`app/composables/useDiscussionWindow.ts`**

```ts
export function useDiscussionWindow() {
  const WINDOW_NAME = 'huntfork-discussion'
  const open = (applicationId: string): void          // window.open по имени; фокус; тост при блокировке; broadcast 'window-opened'
  const isOpenFor = (applicationId: string): Ref<boolean> // состояние из broadcast 'window-opened'/'window-closed'
  const channel = useBroadcastChannel()                // обёртка над BroadcastChannel с typed-сообщениями
  const onStageChanged = (handler): () => void         // подписка на 'stage-changed' с отпиской
  const broadcastStageChanged = (applicationId, payload): void
  const canUseWindow = computed(() => width >= 1024 && typeof window !== 'undefined')
}
```

Состояние открытого окна — `useState('discussion-window')`, чтобы все компоненты в одной вкладке видели его одинаково. Канал один на вкладку, создаётся лениво, закрывается в `onBeforeUnmount` корневого подписчика (`app.vue` плагин или сам composable с подсчётом ссылок).

**`app/pages/dashboard/applications/[id]/discussion.vue`**

Чтобы роут `/dashboard/applications/:id/discussion` не стал дочерним у страницы отклика (Nuxt требует `<NuxtPage>` в родителе), страница отклика переносится из `applications/[id].vue` в `applications/[id]/index.vue` — URL `/dashboard/applications/:id` не меняется.

```ts
definePageMeta({ layout: 'default', middleware: ['auth', 'require-org'] })
```

- Загружает отклик `GET /api/applications/:id` (существующий `[id].get.ts`: `candidateId`, `candidate.firstName/lastName`, `job.title`) — только ради `candidateId` и заголовка вкладки.
- Рендерит мини-строку и `<CandidateDiscussionTabs :current-application-id :candidate-id fill @stage-changed="onStageChanged">`.
- `onStageChanged` → `broadcastStageChanged(applicationId, payload)`.
- `useHead({ title })` с числом непрочитанных.
- На `switch-application` внутри треда — `router.replace` на новый id (компонент `CandidateDiscussionTabs` сейчас держит `activeId` локально; добавить emit `switch-application` наружу, страница окна его слушает).
- `beforeunload` → broadcast `window-closed`.
- 404/403 от API — экран «Отклик недоступен» с кнопкой «Закрыть окно».

### 3.3 Сервер

Изменений нет. Используются существующие `GET /api/applications/:id`, `GET /api/candidates/:id/discussion-tabs`, API комментариев и `thread-stream`. Права — те же middleware `auth` + `require-org` и серверные проверки scope; окно не даёт доступа к тому, что не видно в карточке.

### 3.4 Что учесть

- `window.open` только по клику пользователя — иначе блокировка. Никакого автооткрытия при загрузке страницы.
- Второе окно — второе SSE-подключение и удвоенный рефетч треда на каждое событие (техдолг из `docs/discussion-vision.md`, пакет «Честный realtime»). Для одного рекрутёра это терпимо; при массовом использовании окон приоритет пакета 3 растёт.
- `BroadcastChannel` работает только в одном браузере и одном профиле — этого достаточно, окно открывается из той же вкладки.
- Safari до 15.4 не поддерживает `BroadcastChannel` — делаем `if ('BroadcastChannel' in window)`, без него теряется только мгновенное обновление этапа в основном окне (его подхватит рефетч треда по SSE).
- `popup=yes` в features убирает адресную строку и панели в Chrome/Edge; Firefox показывает урезанную адресную строку — приемлемо.
- Тёмная тема и Astra-бренд наследуются через `html.dark` / `html.astra-brand` (плагин темы работает на любом лейауте) — проверить на стенде.

## 4. Приёмка

1. Страница отклика → «⋯» → «Открыть в окне»: открылось окно 560×900 без меню и шапки приложения, в нём шапка-паспорт, полоса закреплённого, лента, композер; заголовок вкладки окна — имя кандидата.
2. Повторный клик из шторки другого кандидата: новое окно не появилось, существующее переключилось на другой отклик и получило фокус.
3. В окне отправлено сообщение с переводом этапа: в основном окне без перезагрузки обновились карточка отклика (страница), бейдж этапа в воронке (страница вакансии) и список «Другие отклики».
4. В основном окне написано сообщение — оно появилось в попапе без действий пользователя (SSE).
5. Начат черновик в карточке, открыто окно — черновик уже в поле попапа.
6. «Другие отклики» внутри окна: переключение меняет URL, F5 открывает тот же тред.
7. Карточка кандидата → вкладка «Отклики»: у отклика с непрочитанными — число на иконке; клик открывает окно именно этого отклика.
8. Страница интервью → «Обсуждение»: окно открыто на отклике интервью.
9. Браузер с заблокированными попапами: тост с подсказкой, тред открылся новой вкладкой.
10. Окно `≤ 1023px`: пунктов «Открыть в окне» нет. В попапе пункта «Открыть в окне» нет, есть «Открыть карточку отклика» — он открывает карточку в основной вкладке.
11. Роль `hiring_manager`: окно открывается, внутренних сообщений нет (те же правила, что в карточке).
12. Тёмная тема и Astra-бренд в окне совпадают с основным приложением.

## 5. Оценка

Один–полтора дня: composable и страница окна (~200 строк), пункты меню и кнопки на пяти поверхностях (~80 строк), i18n, ручная приёмка на стенде. Схема, миграции, API — без изменений.

## 6. Вне этого ТЗ

Запоминание «всегда открывать обсуждение в окне» как настройка пользователя; окно с двумя тредами (кандидат и заказчик) рядом; Picture-in-Picture через `documentPictureInPicture` (Chrome 116+) — поверх обычного окна, если понадобится «поверх всех окон».
