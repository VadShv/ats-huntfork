# Геймификация рекрутера — «Достижения», HuntPass и соревновательная система

> **Статус:** living-doc проектирования. Обновляется при каждом изменении механик геймификации.
> История: базовый модуль достижений (сентябрь 2026) — `server/utils/achievements`, `shared/achievements-catalog.ts`.
> HuntPass (сезонный трек) — октябрь 2026.

---

## 1. Философия (главный принцип)

**Геймификация усиливает правильное поведение, а не накрутку метрик.**

Игры мотивируют петлёй: **цель → действие → награда → прогресс**. Опасность в рекрутинге — гнать объём в ущерб качеству и опыту кандидата. Поэтому:

1. **Награждаем результат, а не действие.** XP за найм, принятый оффер, быстрый отклик — не за клики.
2. **Качество — множитель.** XP за найм умножается на acceptance rate / retention. Нельзя нафармить пустыми офферами.
3. **Баланс метрик:** объём × качество × скорость × опыт кандидата.
4. **Опциональность.** Геймификацию можно скрыть — это рабочий инструмент, а не обязательная игра.
5. **Прозрачность.** Всегда понятно, за что начислен XP.
6. **Справедливость.** Не наказывать за сложные вакансии; учитывать контекст.
7. **Против выгорания.** Механики вроде «streak freeze» защищают от токсичного «не пропусти день».

**Анти-паттерны, которые система НЕ должна поощрять:** массовые отказы без обратной связи, «зависшие» кандидаты, просроченные отклики, пустые офферы ради цифр.

## 2. Текущий модуль «Достижения» (реализовано)

- **Схема:** `achievement` (каталог) + `user_achievement` (заработанные).
- **Каталог:** `shared/achievements-catalog.ts` — 21 ачивка (7 категорий), 6 уровней XP (Новичок → Talent Magnet).
- **Метрики:** `server/utils/achievements/metrics.ts` — из `application_stage_history` + `activity_log`, без новых таблиц трекинга. Таймзона: `APP_TIMEZONE` (по умолчанию `Europe/Moscow`).
- **Проверка/начисление:** `server/utils/achievements/check.ts` — пороги, начисление, дебаунс (15с). Ключи каталога (snake_case) → поля метрик (camelCase) через `METRIC_KEY_MAP`.
- **Сидирование:** `server/plugins/seed-achievements.ts` — каталог один раз при старте.
- **API:** `GET /api/achievements`, `GET /api/achievements/leaderboard`, `POST /api/achievements/check`.
- **UI:** виджет на дашборде + галерея `/dashboard/achievements` с рейтингом.

## 5. HuntPass — дизайн

### 5.1 Сезон = календарный квартал (4/год)

| Сезон | Период | Тема |
|---|---|---|
| Q1 | 1 янв – 31 мар | «Зимний найм» |
| Q2 | 1 апр – 30 июн | «Весенний поток» |
| Q3 | 1 июл – 30 сен | «Летний марафон» |
| Q4 | 1 окт – 31 дек | «Финишный рывок» |

Сезон генерируется автоматически по текущей дате. Поля: `name, quarter, year, starts_at, ends_at, theme, is_active`.

### 5.2 Тиры и кривая SXP

- **30 тиров** на сезон (~3 дня/тир).
- **Растущая кривая:** тир N требует `SXP(N) = 100·N + 10·N²`. Тир 1 = 110, тир 10 = 2000, тир 30 = 21000 (кумулятивный порог).
- Текущий тир вычисляется из накопленного SXP на лету.

### 5.3 Источники SXP (с качеством)

| Событие | Базовый SXP | Множитель качества |
|---|---|---|
| Найм (hired) | 100 | × acceptance-фактор (0.5–1.5) |
| Оффер отправлен | 40 | — |
| Интервью проведено | 20 | — |
| Вакансия закрыта | 80 | — |
| Квест выполнен | по квесту | — |

**Качество-множитель** для найма: acceptance ≥80% → ×1.5; 50–80% → ×1.0; <50% → ×0.5 (при ≥5 офферов; иначе ×1.0). Пустые офферы не фармятся.

### 5.4 Free vs Premium

- **Free** (все): бейджи, титулы, рамки, монеты, quest-reroll.
- **Premium** (активирует owner/admin по-рекрутерно): больше монет, XP-boost, эксклюзивные титулы, реальные перки (настраиваются орг; по умолчанию — косметика + монеты).
- Оба трека параллельны по одним тирам — premium добавляет вторую награду.

### 5.5 Конец сезона

- SXP → 0, новый трек. Незабранные награды — grace 7 дней / авто-выдача.
- **Season Recap** — «сезон в цифрах». Финальный тир 30 → вечный титул «Рекрутер сезона Q3 2026».

### 5.6 Данные

```
season(id, name, quarter, year, starts_at, ends_at, theme, is_active)
user_season_progress(id, user_id, org_id, season_id, is_premium, claimed_tiers jsonb, updated_at)
```

SXP не хранится — вычисляется из существующих данных в окне сезона. Каталог тиров/наград — `shared/season-track.ts`, растущая кривая + награды. Тир вычисляется из SXP.

## 6. Квесты — дизайн (след. этап)

### 6.1 Типы

| Тип | Активных | Обновление | Примеры |
|---|---|---|---|
| Ежедневные | 3 | полночь (лок. tz) | «Ответь на 3 отклика», «Проведи 1 интервью», «Продвинь 3 кандидата» |
| Недельные | 3–5 | понедельник | «Закрой 1 вакансию», «5 до интервью», «3 оффера», «20 откликов» |
| Сезонные | 2–3 | старт сезона | «10 вакансий», «80% acceptance», «все вакансии отдела» |

### 6.2 Механики

- Прогресс — из движка метрик, окно = период квеста.
- **Reroll** 1/день (premium 2). **Стрик выполнения** N дней → бонус. **Streak Freeze** 1/неделю.
- Баланс: набор daily всегда включает ≥1 качественный квест (`quality_flag`).

### 6.3 Данные

```
quest_template(id, key, type, title, description, metric, target, sxp_reward, coin_reward, weight, quality_flag, is_active)
user_quest(id, user_id, org_id, quest_template_id, period_key, progress, status, assigned_at, completed_at)
```

`metric` переиспользует ключи движка. `period_key`: дата / `2026-W03` / season_id. Каталог — `shared/quests-catalog.ts`.

## 7. Метрики качества (сквозная задача G)

| Объём | + Качество / скорость / опыт |
|---|---|
| Офферы | **% принятых** (acceptance rate) |
| Наймы | **Retention 90 дней** |
| Интервью | **Time-to-first-response** |
| — | **Оценка нанимающего менеджера** |
| — | **Candidate NPS** |

Качество — множитель SXP/XP. Штрафы за анти-паттерны снижают ранг (этап D).

---

## 8. Принципы реализации (техдолг-safe)

- Метрики из существующих данных (`application_stage_history`, `activity_log`), окно = период.
- Каталоги (`shared/`) сидируются плагином при старте.
- Прогресс вычисляемый (lazy на дашборде) + дебаунс на событиях.
- Схему расширяем аддитивно (новые таблицы), существующие не трогаем.
- Всё org-scoped, RBAC-совместимо. Таймзона — `APP_TIMEZONE`.
