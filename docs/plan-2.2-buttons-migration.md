## 3. Правила замены (что МЕНЯЕМ, что НЕ трогаем)

### Меняем (типовые кнопки)
| Сырой паттерн | → UiButton |
| --- | --- |
| `bg-brand-600 ... text-white` (основное действие) | `<UiButton>` (variant по умолчанию primary) |
| `border border-surface-300 bg-white` (вторичное) | `variant="secondary"` |
| прозрачная `hover:bg-surface-100` (тихое) | `variant="ghost"` |
| `bg-danger-600` / удаление | `variant="danger"` |
| `bg-success-600` / подтверждение | `variant="success"` |
| `bg-emerald-600` (hire) | `variant="success"` (убрать emerald-разнобой) |
| `underline` link-кнопка («Повторить», сортировка) | `variant="link"` |
| icon-only `p-2 rounded-lg` | `icon-only` + `variant="ghost"` |
| спиннер `Loader2 v-if=... + icon v-else` | `:loading` + `:icon-left` |
| `:disabled` + классы disabled | `:disabled` (стили из компонента) |
| segmented control (группа кнопок-периодов с активной подсветкой) | новый `UiSegmented` (см. Батч 8a) |
| устаревший токен `primary-*` | `brand-*` (одна палитра) |

### НЕ трогаем (нетиповые — риск сломать)
- **Кнопки-«глаза» показа пароля** и любые контролы, **вложенные в поле ввода**
  с абсолютным позиционированием (часть инпута, не самостоятельная кнопка).
- **Кнопки со сложной условной подсветкой активного состояния** (табы, чипы
  фильтров, view-toggle) — если не ложатся в variant, оставляем или выносим
  в отдельную задачу.
- **Кастомные интерактивные элементы** (drag-handles, карточки-кнопки, ячейки
  таблиц с `@click`) — это не кнопки в смысле ДС.
- **Карточки откликов/резюме** — по общему правилу проекта не трогаем.

### Обязательно сохранять при замене
- Модификаторы событий: `@click.stop` (67×), `@click.self` (27×),
  `@click.prevent` (3×) — переносить дословно.
- `type="submit"` (24×) — в формах проставлять `type="submit"` пропом.
- `:disabled`, `title`, `aria-*` — `UiButton` прокидывает через `inheritAttrs`.
- `to`/`href` для кнопок-ссылок — использовать пропы `to`/`href` UiButton.
- Убирать мёртвые импорты (`Loader2`), если иконка ушла в `:loading`.

## 4. Проверка после каждого батча

Без typecheck/lint-скриптов в проекте — проверяем так:
1. **Статически:** `grep -c "<button"` в изменённых файлах = только осознанно
   оставленные; все `variant/size` валидны по API UiButton.
2. **Нет мёртвых импортов** (`Loader2` и т.п.).
3. **Клиентская сборка** (`npm run build` до стадии client) — без ошибок.
4. **Коммит** батча отдельным сообщением: `refactor(ui): UiButton in <module>`.
5. **Push → деплой → визуальная проверка** ключевых экранов батча
   (светлая/тёмная тема, кнопки кликаются, спиннеры/disabled работают).

## 5. Риски и митигация

| Риск | Уровень | Митигация |
| --- | --- | --- |
| Потеря `@click.stop/.self/.prevent`, `type=submit` | 🟡 | Дословный перенос; проверять формы после батча |
| Кнопки со сложным `:class` не ложатся в variant | 🟡 | Не «впихивать» силой — оставлять сырыми или заводить вариант |
| Визуальный сдвиг (был `px-2 py-1`, стал `size="sm"`) | 🟡 | Проверять глазами; подбирать size под исходный габарит |
| Объём (168 файлов) → усталость/пропуски | 🟡 | Батчи по модулю, отдельные коммиты, чек после каждого |
| Нет автотестов | 🟡 | Клиентская сборка + ручная проверка ключевых экранов |
| Конфликт с параллельной разработкой | 🟢 | Договорились: сначала причёсываем старое, потом новые страницы |
| Школа фильтров аналитики | 🔴 | **Вынесена в 2B (отложено)** — сейчас НЕ трогаем |
