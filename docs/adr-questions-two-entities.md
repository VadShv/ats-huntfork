# ADR: Три сущности «вопросов» — форма отклика, банк интервью, org-банк

> **Статус:** принято 13.09.2026, реализация — модуль вопросов (Спринты 0–5).
> Связано: `docs/tz-questions-00-master-plan.md`, `docs/tz-questions-01-org-bank.md`,
> `docs/tz-questions-90-cross-cutting.md` (§7b карта коллизий «question»).

## Контекст

Слово «question» в кодовой базе перегружено. Уже существуют:
- `job_question` (`app.ts:490`) — **поля публичной формы отклика** для соискателя
  (9 типов: short_text…file_upload); ответы в `question_response` (`app.ts:512`).
- `job_interview_question` (`app.ts:569`) — **интервью-вопросы вакансии** (карта
  вакансии), AI-генерируемые; промпт в `job_question_prompt` (`app.ts:589`).
- `application_question_set` / `application_question_item` (`app.ts:1965`) —
  **персональный опросник кандидата** под отклик.

Модуль вопросов добавляет **org-уровень**: `bank_question` (корпоративный банк) и
производные (`question_preset` и т.д.). Возникает риск спутать `bank_question` с
`job_question` / `job_interview_question` при реализации.

## Решение

**Это РАЗНЫЕ сущности с разным назначением и уровнем. Не дубль, не заменяем, не
сливаем.** Разделение фиксируется терминологически и структурно.

1. **`job_question` остаётся** — поля формы отклика (candidate-facing). Публичный
   контур (`public/jobs/[slug]/apply.post.ts`) зависит от неё; удаление/переименование
   таблицы **запрещено** (сломает публичную форму и e2e `candidate-application.spec.ts`).
2. **`bank_question`** (новое, org) — источник истины для формулировок и
   методологии; переиспользуемый эталон. Направление наследования:
   `bank_question` → `question_preset` → `job_interview_question` →
   `application_question_item`.
3. **Терминология в UI/i18n** разводит сущности явно:
   - форма отклика → «Форма заявки» / «Вопросы формы» (вкладка
     `dashboard.jobs.tabs.applicationForm`, `AppTopBar.vue:119`);
   - интервью-вопросы вакансии → вкладка «Вопросы»
     (`dashboard.jobs.tabs.questions`, `AppTopBar.vue:118`);
   - org-банк → раздел настроек «Банк вопросов».
4. **Без префикса-неймспейса.** Рассматривался `qb_` (по образцу `comms_`/`hh_`),
   отвергнут: имена (`bank_question`, `assessment_topic`, `care_prompt`)
   самоописательны, а коллизии сняты картой §7b кросс-раздела. См.
   `tz-questions-90-cross-cutting.md §7a`.
5. **Конвенция имён БД** — единый источник правды в
   `tz-questions-90-cross-cutting.md §7a/§7c`: таблицы/enum `snake_case`, enum БД-имя
   БЕЗ суффикса `_enum`, Drizzle-alias camelCase с `Enum`.

## Последствия

- Разработчик, встретив `bank_question` и `job_interview_question`, различает их по
  уровню (org vs вакансия) и карте §7b; правит нужную ветку.
- Публичная форма отклика не затрагивается модулем.
- Персональный опросник (`application_question_*`) — потребитель банка/карты
  вакансии + risk-findings; расширяется в Спринте 4, не пересоздаётся.

## Отвергнутые альтернативы

- **Удалить/переименовать `job_question`** — сломает публичный контур. Нет.
- **Слить `bank_question` и `job_interview_question` в одну таблицу** — разные
  уровни (org vs вакансия), разный жизненный цикл (публикация/версии vs правка
  под вакансию). Нет.
- **Префикс `qb_`** — лишняя косметика, ломает читаемость; коллизии решаются
  документацией. Нет.
