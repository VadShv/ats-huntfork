## ТРЕБОВАНИЕ (Порция #5): общий кандидат + приватные вакансии (модель Хантфлоу)

### Правило
Кандидат — **общий ресурс организации**. Рекрутер, работающий с кандидатом,
видит **всю его историю** (отклики по всем вакансиям, скрининг, версии резюме) —
но **не может провалиться в вакансию вне своего scope**.

Разделяем две вещи:
- **Данные кандидата** (карточка, история откликов, резюме, версии, скрининг) —
  ОБЩИЕ для орга (видны всем, кто с кандидатом работает).
- **Вакансия и её воронка** — ПРИВАТНЫ по scope: заявку на чужую вакансию видно
  как строку истории, но переход в саму вакансию запрещён.

### Acceptance-сценарий (обязателен к воспроизведению)
- Рекрутер А (scope: вакансия В), Рекрутер Б (scope: вакансия Г), кандидат Иван.
- День 1: А добавил Ивана на В. День 2: Б добавляет Ивана → дедуп «Иван уже есть»
  → Б объединяет карточки.
- В карточке Ивана Рекрутер Б **видит всю историю**: отклик на В (чужая) + отклик
  на Г (своя), скрининг, версии резюме — полностью.
- Рекрутер Б видит строку «отклик на вакансию В», но **клик по ней в вакансию В
  НЕ проваливается** (В вне его scope): ссылка неактивна в UI И серверный
  эндпоинт вакансии В отдаёт 404 при прямом переходе.
- Симметрично для Рекрутера А относительно вакансии Г.

### Что делать / чего НЕ делать
- **НЕ фильтровать** заявки/историю в карточке кандидата по scope — показывать
  все (это правило «видит всю историю»). Сейчас так и есть — НЕ добавлять фильтр.
- **Блокировать переход в вакансию** вне scope: UI — неактивная ссылка/«нет
  доступа»; сервер — `isJobInScope` на job-эндпоинтах → 404 (из Порции #4).
- **Контакты** — по праву `candidate:read:contacts` (masking), как везде.
- **Видимость кандидата**: рекрутер видит кандидата целиком, если пересекается с
  ним хотя бы на одной СВОЕЙ вакансии (EXISTS application на видимую вакансию —
  уже реализовано в пилоте).

### РЕШЕНО (владелец, 12.09.2026): Вариант A ✅
Скоркарты/баллы/скрининг по ЧУЖОЙ вакансии в карточке кандидата — **ПОКАЗЫВАТЬ
полностью**. Блокируется ТОЛЬКО переход в саму вакансию (UI неактивная ссылка +
сервер 404 на job-эндпоинте). История кандидата общая — ничего в ней не скрываем
и не маскируем по scope (кроме контактов, которые маскируются по
`candidate:read:contacts` как везде).
