> Процесс: доступы/ИИ = высокий риск → сверка ДО прод-деплоя. Полная

## Причина (что выявил владелец)

Зашёл глазами `external_recruiter` → ИИ-ассистент открыт, история переписок видна,
можно задавать вопросы по всей орге. По КОДУ external не имеет `scoring:read`, а
chatbot/* под `requireChatbotAccess(scoring:read)` → должно быть 403. ВЕРОЯТНАЯ
причина: в проде СТАРЫЙ бандл (не пересобран `--no-cache` после Спринта E, где
вводился гейт) — как инцидент C1. Первым делом проверить прод и пересобрать.

## Продуктовая модель (решение владельца)

**ИИ-ассистент (чатбот) — ТОЛЬКО доверенные: owner / admin / lead_recruiter.**
У member / hrbp / external / hiring_manager — ОТКЛЮЧЁН по умолчанию.

**Скоринг кандидатов (AI-оценка по критериям) — ОСТАЁТСЯ у рекрутера (member).**
Это рабочий инструмент, НЕ «свободный ИИ по базе». Поэтому доступ к чатботу и
скоринг надо РАЗДЕЛИТЬ (разные права).

**Каждый видит ТОЛЬКО свои чаты ассистента** (история по userId, не перемешивается)
— критичное требование владельца.

| Роль | ИИ-ассистент (чатбот) | Скоринг кандидатов | Суфлёр (assistant:suggest) |
| --- | --- | --- | --- |
| owner/admin | ✅ | ✅ | ✅ |
| lead_recruiter | ✅ (только свои чаты) | ✅ | ✅ (Спринт E) |
| member | ❌ | ✅ | ❌ |
| hrbp | ❌ | по scope | ❌ |
| external | ❌ | ❌ | ❌ |
| hiring_manager | ❌ | ❌ | ❌ |

## ЧАСТЬ 1 — ГРАНУЛЯРНЫЕ права ассистента (управление в матрице)

Сейчас доступ к чатботу гейтится `scoring:read` (`requireChatbotAccess`), что
связывает «скоринг» и «чатбот». Требование владельца: вынести управление
ассистентом в матрицу ПОФУНКЦИОНАЛЬНО (не одно бинарное право), чтобы можно было
настраивать каждую возможность отдельно.

### Набор прав (ресурс `assistant`) — по реальным функциям кода:
| Право | Что гейтит | Эндпоинт/поле |
| --- | --- | --- |
| `assistant:access` | доступ к разделу ассистента ВООБЩЕ (нет → не зайти на страницу) | все chatbot/* (базовый гейт) |
| `assistant:send` | отправлять сообщения ассистенту | chatbot/chat.post |
| `assistant:scopeOrg` | выбирать контекст «вся организация» (иначе только свои вакансии) | chat.post `scope.kind='organization'` |
| `assistant:reasoning` | включать режим рассуждения (thinking) | chat.post `thinking=true` |
| `assistant:agents` | создавать/редактировать/удалять своих агентов | chatbot/agents/* (post/patch/delete) |
| `assistant:selectModel` | выбирать AI-модель | chat.post `aiConfigId` |
| `assistant:suggest` | суфлёр переписки (УЖЕ есть, Спринт E) | conversations/suggest |

### Логика гейтов
- [ ] `assistant:access` — БАЗОВЫЙ: нет → `/api/chatbot/*` = 403, на страницу
      /dashboard/chatbot не пускать (баннер). requireChatbotAccess → требует
      `assistant:access` (вместо scoring:read).
- [ ] `assistant:send` — chat.post: нет → нельзя отправлять (403), но раздел
      открыт read-only (видит свои старые чаты).
- [ ] `assistant:scopeOrg` — chat.post: если scope.kind='organization' и НЕТ права
      → 403 (или принудительно сузить до 'job'). Без права юзер может выбирать
      ТОЛЬКО контекст своих вакансий (kind='job'), не всю орг.
- [ ] `assistant:reasoning` — chat.post: thinking=true без права → игнор/403.
- [ ] `assistant:agents` — chatbot/agents create/patch/delete под этим правом
      (index.get — под access). Нет → не может создавать/менять агентов.
- [ ] `assistant:selectModel` — chat.post: смена aiConfigId без права → использовать
      дефолтную модель орга (не давать выбирать).

### Пресеты (дефолты)
- [ ] owner/admin: ВСЕ права ассистента.
- [ ] lead_recruiter: access + send + scopeOrg + reasoning + agents + selectModel +
      suggest (полный доступ — доверенные).
- [ ] member/hrbp/external/hiring_manager: НЕТ прав ассистента (по умолчанию
      закрыт полностью). Точечно можно выдать через матрицу/override.
- [ ] `scoring:read` (скоринг кандидатов) — ОТВЯЗАН от ассистента, остаётся у member.

**Acceptance 1:** матрица показывает блок «AI-ассистент» с ~6 переключаемыми
правами; member/external/hrbp/hm без прав → на страницу ассистента не заходят
(баннер); при точечной выдаче access без send → раздел открыт, но отправка
недоступна; без scopeOrg → выбор контекста только «свои вакансии»; без selectModel
→ модель фиксирована; без agents → нельзя управлять агентами.

## ЧАСТЬ 2 — Персональная история чатов (подтвердить/добить)

По коду chatbot_conversation имеет userId; все эндпоинты
(conversations/index/[id]/get/patch/delete, folders/*) уже фильтруют по
`session.user.id`. Задача — ПОДТВЕРДИТЬ и закрыть пробелы:

- [ ] Все chatbot/conversations и chatbot/folders эндпоинты фильтруют по
      `userId === session.user.id` (не только orgId). Список/детали/патч/удаление
      чужого чата → недоступны (404/пусто).
- [ ] chatbot/agents/* — проверить: агенты персональные или общие орг? (по схеме
      chatbot_agent есть org_user индекс — вероятно персональные). Уточнить/
      заскоупить по userId, если персональные.
- [ ] chatbot/chat.post (сам диалог) — привязка к conversation владельца.

**Acceptance 2:** lead видит ТОЛЬКО свои чаты; чужие чаты (даже другого lead/owner)
не видны в списке и по прямому URL. История не перемешивается.

## ЧАСТЬ 3 — UI ассистента (отражает гранулярные права)

Требование владельца: закрытые функции должны ОТОБРАЖАТЬСЯ в UI как недоступные
(не просто молча падать 403). Клиент читает права из снапшота (usePermissions).

- [ ] **Нет `assistant:access`** → пункт «Ассистент» (топбар + быстрые ссылки)
      СКРЫТ; заход на /dashboard/chatbot → баннер «Недостаточно прав» (не пускать).
- [ ] **access есть, `send` нет** → раздел открыт, видны свои старые чаты (read),
      поле ввода DISABLED + подсказка «Отправка сообщений недоступна».
- [ ] **Нет `scopeOrg`** → переключатель контекста показывает только «Мои
      вакансии»/выбор вакансии; опция «Вся организация» скрыта/disabled.
- [ ] **Нет `reasoning`** → тумблер «Режим рассуждения» скрыт/disabled.
- [ ] **Нет `agents`** → раздел/кнопка «Управление агентами» скрыты; нельзя
      создать/редактировать агента.
- [ ] **Нет `selectModel`** → селектор модели скрыт/disabled (используется дефолт
      орга).
- [ ] Флаги приходят с сервера (conversation/capabilities API или usePermissions);
      сервер — источник защиты, UI — отображение.

**Acceptance 3:** matrix-права ассистента визуально отражены в интерфейсе чатбота
(скрыты/disabled соответствующие контролы); полностью закрытый ассистент → на
страницу не зайти; частично открытый → доступные функции работают, закрытые видны
как недоступные.
