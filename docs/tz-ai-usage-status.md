# Учёт расхода ИИ — статус реализации

Реализация ТЗ [`docs/tz-ai-usage.md`](./tz-ai-usage.md). Этапы Э1–Э3 сделаны полностью, из Э4 — только очистка по сроку хранения.

## Что сделано

### Э1. Ядро учёта
- **Миграция `0123_ai_usage.sql`**: таблицы `ai_usage_event`, `ai_usage_settings`, `ai_usage_budget`, `ai_usage_alert`; в `ai_config` — `cached_input_price_per_1m` и `price_currency`; тип уведомления `ai_budget`. Миграция проверена на чистой БД после всех 122 предыдущих.
- **Перенос истории** (§11) прямо в миграции: `analysis_run`, `resume_risk`, `meeting_report`, `candidate_duplicate_candidate` с флагом `is_backfilled` и ценой текущей конфигурации.
- **Middleware AI SDK** (`server/utils/ai/usage/middleware.ts`) в `createLanguageModel` / `createCloudRuStreamModel`: один вызов модели = одно событие, generate и stream, TTFT, finish_reason, ошибки/таймауты/отмены, хэш системного промпта. Тексты промптов и ответов не сохраняются.
- **Контекст операции** (`context.ts`) на AsyncLocalStorage: `withAiOperation` / `withAiTrace`, трейсы и номера шагов; актор HTTP-запроса — из `requireAuth` / `requirePermission`; очереди pg-boss выполняются с `trigger: 'background'`.
- **Каталог операций** `shared/aiUsage/catalog.ts` — 36 операций с фичей, назначением, промптом из реестра и пояснением к стоимости.
- **Буферизованная запись** (`writer.ts`): батч-вставка, фиксация цены и курса в момент вызова, оценка токенов по символам, если провайдер не прислал usage. Сбой записи не ломает ИИ-функцию.
- Все места вызова модели обёрнуты; тест `ai-usage-coverage.test.ts` не даст добавить новый вызов без атрибуции.

### Э2. Дашборд
- Страница **«Учёт токенов»** (в коде и ТЗ — «Расход ИИ») (`/dashboard/ai-usage`, пункт в верхнем меню): фильтры в URL, KPI, график по дням с разбивкой по фичам/моделям/триггерам, дерево операций, вкладки «Модели / Сотрудники / Вакансии / Триггеры / Конфигурации», журнал вызовов с курсорной подгрузкой, шторка трейса и карточка операции.
- **API** `server/api/ai-usage/*`: summary, timeseries, breakdown, anomalies, events, traces/:id, operations, operations/:key, export.csv, settings, budgets, recalculate.
- **Банк промптов**: использование за 30 дней у каждого промпта, ссылка на дашборд; в песочнице после прогона — токены и стоимость.
- **«ИИ-анализ»** считает расходы скрининга по новому журналу (`usageJournal`).
- **RBAC** — ресурс `aiUsage`: `view_own`, `view_org`, `view_costs`, `manage_budgets`, `export`, `recalculate`. Без `view_costs` денежные поля вырезаются на сервере (`stripCosts`).

### Э3. Контроль
- **Бюджеты** (организация / фича / операция / сотрудник, день или месяц), пороги 50/80/100 %, одно уведомление на старший пересечённый порог, режим `block_background` останавливает фоновые вызовы (автоскоринг, риски, ИИ в треде); ручные действия не блокируются.
- **Уведомления** `ai_budget` в колокольчике и на странице уведомлений, ссылка ведёт на дашборд.
- **Настройки** «Настройки → ИИ → Бюджет и валюта»: базовая валюта, курс USD/RUB, срок хранения, бюджеты, пересчёт истории по текущим ценам (с аудитом).
- **Встройки**: виджет расхода в вакансии (вкладка ИИ-анализа), в карточке кандидата, строка ИИ-расхода в статистике карты поиска.
- **Потери и аномалии**: ошибки, обрывы по длине, дорогие вызовы, повторы.
- **Экспорт CSV** с защитой от формул.

### Э4
- Очистка журнала по `retention_days` — scheduled task `ai-usage:retention`.

## Отклонения от ТЗ

| Пункт | Как сделано | Почему |
|---|---|---|
| Автор автоскоринга | `userId` берётся только из запроса, где он есть | у вакансии нет поля владельца |
| Песочница с `modelOverride` | цена берётся из выбранной конфигурации | цены отдельной модели нет в данных |
| Стоимость в песочнице | показывается только при `view_costs` | единое правило §9 |
| Курс USD/RUB | вводится вручную в настройках | автокурс ЦБ — Э4, «по факту» |
| Дневные агрегаты (§4.6) | не сделаны | Э4, понадобятся при росте журнала |
| «Отложить» автоскоринг при блокировке | вызов не уходит к модели, прогон помечается ошибкой с текстом о бюджете; повтор — вручную («Оценить всех») | автоповтор после снятия лимита усложнил бы очередь |
| Фильтр «кандидат» на дашборде | фильтрует события с `entity = candidate`; виджет карточки дополнительно суммирует события откликов кандидата | у отклика своя сущность |

## Проверка
- Unit-тесты: `npx vitest run` — 63 файла, 1168 тестов, все зелёные. Новые: `ai-usage-cost`, `ai-usage-normalize`, `ai-usage-period`, `ai-usage-context`, `ai-usage-middleware` (на `MockLanguageModelV3`), `ai-usage-budget`, `ai-usage-coverage`, `prompt-registry-completeness`.
- Интеграционный прогон на реальной схеме (PGlite, все миграции, локально, не в репозитории): запись событий с ценой и курсом, summary/timeseries/breakdown по всем измерениям, журнал с курсором, трейс, карточка операции, CSV, скрытие сумм без `view_costs`, бюджеты и уведомления без дублей, пересчёт курса и цен, виджет вакансии, retention — 15 сценариев, все прошли. Тогда же найдены и исправлены часовой пояс в группировке по дням и текущий день в сетке графика.
- Типы: новые и изменённые файлы проходят `tsc` / `vue-tsc` без новых ошибок; оставшиеся ошибки — те же, что на `main`.

## Что проверить руками после деплоя
1. `npm run db:migrate` (или штатный запуск миграций) — применится `0123_ai_usage`.
2. Указать цены и валюту в «Настройки → ИИ» у каждой конфигурации (для Cloud.ru — в ₽).
3. Задать курс USD/RUB на вкладке «Бюджет и валюта».
4. Проверить права `aiUsage:*`: по умолчанию owner — все, admin — все кроме `recalculate`, рекрутер — только `view_own` (токены без сумм).
5. Сделать пару ИИ-действий и проверить, что на «Учёт токенов» нет строки «Без атрибуции».
